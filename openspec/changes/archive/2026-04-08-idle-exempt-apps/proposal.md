## Why

挂机类游戏、视觉小说等场景下，用户可能长时间无键鼠输入或画面变化极小，现有「键鼠空闲 + 截图相似度 + 20 分钟硬切断」会把真实前台使用时间记短或记零。需要在不削弱全局防「人离开仍累加」能力的前提下，对**用户明确指定的应用**改为始终按截图间隔正常累计时长。

## What Changes

- 在**设置 → 常规**中新增「空闲检测豁免应用」配置：可维护一组应用标识（与活动记录中的展示名一致），列表中的应用在处于前台且被正常记录时**不参与空闲检测**（不将 `effective_duration` 置零、不因空闲跳过回补），仍按现有「距上次截图秒数」逻辑计时。
- 豁免列表的**候选来源**为本设备 SQLite 中**已出现过的** `app_name`（去重、可搜索/可选），由 Tauri 命令查询返回；用户从候选中勾选或添加，不依赖手动输入包名（可选允许高级用户补全，见 Non-goals）。
- 配置持久化进现有应用配置（与 `config` 结构一致），启动与录制循环中读取。

## Capabilities

### New Capabilities

- `idle-exempt-apps`: 豁免应用列表的配置模型、设置 UI（常规页）、本机已记录应用枚举 API，以及录制主循环中对豁免应用跳过空闲判定与相关时长扣减。

### Modified Capabilities

_(无全局 `openspec/specs/` 基线；本变更为新增能力。)_

## Non-goals

- **不改为「按进程路径 / Bundle ID 精确匹配」**：首版以与活动记录一致的 `app_name`（展示名）匹配为主，避免跨平台路径差异；若未来需加固可另起变更。
- **不做跨设备同步豁免列表**：与 `docs/SYNC_DESIGN.md` 中的同步模型无强制关联；豁免列表默认仅本机有效（若将来 config 全量同步再统一考虑）。
- **不豁免隐私规则**：若应用命中隐私「完全跳过」，仍不记录，与豁免无关。
- **不提供「从文件导入包名列表」**：首版仅设备已记录应用 + 配置内已保存项。

## Impact

- **前端**：`SettingsGeneral.svelte`（或等价常规设置组件）新增区块与多选/标签列表 UI。
- **后端**：`AppState` / `config` 序列化新增字段；`commands.rs` 新增「列出本机历史应用名」命令；`main.rs` 录制循环在计算 `is_confirmed_idle`、`previous_app_backfill_duration` 等路径上对当前前台应用做豁免判断。
- **数据库**：只读查询 `DISTINCT app_name`（或已有聚合 API 的扩展），无 schema 迁移需求（除非选择单独表存豁免，建议放 config JSON）。
