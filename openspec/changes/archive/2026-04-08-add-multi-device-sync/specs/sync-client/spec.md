## 新增需求

### 需求：定时同步任务
客户端应按 `sync.sync_interval_minutes` 配置的间隔运行后台同步任务。任务先推送本地变更，再拉取远端变更。

#### 场景：按间隔自动同步
- **当** 同步已启用且配置的间隔时间已到
- **则** 客户端执行完整的推送→拉取周期

#### 场景：同步已关闭
- **当** `sync.enabled` 为 false
- **则** 不运行同步任务，不发起网络请求

### 需求：增量推送
客户端应仅推送 `timestamp > last_push_timestamp` 且 `device_id = 本机设备` 的活动。推送成功后更新 `last_push_timestamp`。

#### 场景：推送新的本地活动
- **当** 上次推送以来有 5 条新的本地活动
- **则** 客户端将这 5 条发送到 `POST /api/sync/push`
- **则** `last_push_timestamp` 更新为服务端响应的时间戳

#### 场景：无新活动
- **当** 没有比 `last_push_timestamp` 更新的本地活动
- **则** 跳过推送请求（避免不必要的网络调用）

### 需求：增量拉取与 UPSERT
客户端应通过 `GET /api/sync/pull?since=last_pull_timestamp&exclude_device=本机` 拉取远端记录，并按 `uuid` UPSERT 到本地数据库。

#### 场景：拉取并插入新的远端活动
- **当** 服务端返回其他设备的 8 条活动
- **则** 全部插入本地数据库，保留其原始 `device_id`

#### 场景：拉取并更新已有活动
- **当** 服务端返回的活动 uuid 本地已存在但 timestamp 更新
- **则** 用更新的数据更新本地记录

### 需求：截图同步
客户端应根据 `sync_screenshots_mode`（`full`、`thumbnail`、`none`）上传本地截图到服务端。

#### 场景：完整模式上传
- **当** `sync_screenshots_mode` 为 `full`
- **则** 逐文件调用 `PUT /api/sync/screenshot/{device_id}/{date}/{filename}` 上传原始 JPEG 文件

#### 场景：缩略图模式上传
- **当** `sync_screenshots_mode` 为 `thumbnail`
- **则** 截图先缩小后，再逐文件上传到截图接口

#### 场景：不传模式
- **当** `sync_screenshots_mode` 为 `none`
- **则** 不上传截图文件

### 需求：自动拉取保留期内远端截图
客户端应在 pull 周期后，自动下载保留期内的远端设备截图；保留期使用本地 `screenshot_retention_days` 配置。

#### 场景：拉取其他设备最近截图
- **当** pull 返回了其他设备且在保留期内的活动记录，并且记录带有 `screenshot_path`
- **则** 客户端自动从服务端下载对应截图到本地截图目录

#### 场景：超出保留期的远端截图不下载
- **当** pull 返回的活动记录截图日期早于本地 `screenshot_retention_days` 对应的截止日期
- **则** 客户端跳过该截图下载

#### 场景：下载列表来源于 pull 结果
- **当** 客户端完成一次 pull
- **则** 仅基于本次 pull 返回的活动记录收集待下载截图，不扫描全量本地活动表

### 需求：离线容错
客户端应优雅处理同步失败。服务端不可达时，静默记录日志并在下次同步周期重试，不丢失数据，不弹窗打扰用户。

#### 场景：推送时服务端不可达
- **当** 推送时同步服务端不可达
- **则** 客户端记录 warning 日志，`last_push_timestamp` 保持不变
- **则** 下次同步周期重新推送相同记录

#### 场景：拉取时服务端不可达
- **当** 拉取时同步服务端不可达
- **则** 客户端记录 warning 日志，`last_pull_timestamp` 保持不变

### 需求：拉取设备列表
客户端应在每次同步周期中通过 `GET /api/devices` 拉取设备列表，并缓存到本地，用于 `device_id → device_name` 的展示映射。

#### 场景：缓存远端设备名称
- **当** 客户端完成拉取周期
- **则** 本地设备缓存更新为所有已知设备的 `device_name`

#### 场景：缓存为空时的展示回退
- **当** 设备缓存中没有某个 `device_id` 的条目
- **则** UI 直接显示原始 `device_id` 作为标签

### 需求：手动触发同步
客户端应提供一个 Tauri command 以手动触发同步，不受定时计划限制。

#### 场景：用户手动触发同步
- **当** 用户在设置中点击「立即同步」
- **则** 立即执行完整的推送→拉取周期，UI 展示执行结果
