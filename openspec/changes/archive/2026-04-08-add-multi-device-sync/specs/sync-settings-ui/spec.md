## 新增需求

### 需求：同步配置卡片
设置页面应在「存储」标签下包含一个「同步」卡片，包含以下字段：同步开关、服务器地址、同步 Token、设备 ID（只读）、设备名称、同步间隔、截图同步模式。

#### 场景：同步设置可见
- **当** 用户导航到 设置 → 存储
- **则** 显示「同步」卡片，包含所有同步配置字段

#### 场景：保存同步设置
- **当** 用户修改同步字段并保存
- **则** 同步配置持久化到 `config.json`，同步任务相应调整

### 需求：同步状态展示
同步卡片应展示当前同步状态：上次同步时间、同步结果（成功/失败）、已连接设备数。

#### 场景：显示上次同步信息
- **当** 用户查看同步设置卡片
- **则** 展示上次成功同步的时间戳和已同步的设备数量

#### 场景：显示同步错误
- **当** 上次同步尝试失败
- **则** 在同步状态区域显示错误信息

### 需求：手动同步按钮
同步卡片应包含一个「立即同步」按钮，触发立即执行同步周期。

#### 场景：手动同步成功
- **当** 用户点击「立即同步」且同步完成
- **则** 状态更新为最新的同步时间和结果

### 需求：设备筛选下拉列表
概览页、时间线页面和日报页面应在顶部提供一个设备筛选下拉列表。默认选中「全部设备」，也可选择单台设备仅查看该设备的数据。

#### 场景：默认查看全部设备
- **当** 用户进入概览页、时间线页面或日报页面
- **则** 下拉列表默认选中「全部设备」，展示所有设备的合并数据

#### 场景：筛选单台设备
- **当** 用户从下拉列表选择某台设备
- **则** 页面仅展示该设备的数据

#### 场景：下拉列表设备来源
- **当** 渲染设备筛选下拉列表
- **则** 列表项来自本地已知设备列表，优先使用 `device_name`（无名称时回退显示 `device_id`）

### 需求：日报设备筛选
日报页面应支持与概览/时间线一致的设备筛选。

#### 场景：日报页默认查看全部设备
- **当** 用户进入日报页面且设备筛选为「全部设备」
- **则** 优先展示该日期的综合日报卡片

#### 场景：日报页查看单设备
- **当** 用户在日报页面选择某台设备
- **则** 仅展示该设备的日报

#### 场景：全部设备综合日报已存在
- **当** 当前筛选为「全部设备」且该日期已存在 `device_id=''` 的日报
- **则** 日报页面直接展示这条综合日报

#### 场景：全部设备综合日报不存在
- **当** 当前筛选为「全部设备」且该日期不存在 `device_id=''` 的日报
- **则** 页面保持无日报状态，直到用户手动生成综合日报

#### 场景：单设备日报读取
- **当** 用户切换到某台具体设备
- **则** 系统读取 `device_id=该设备` 的日报，不读取综合日报

#### 场景：综合日报手动生成
- **当** 用户在「全部设备」模式下点击生成日报
- **则** 系统基于全部设备活动数据生成内容，并保存为 `device_id=''` 的日报

### 需求：同步设置保存后立即回显设备标识
设置页面保存同步配置后，应立即显示后端规范化后的 `device_id` 与 `device_name`。

#### 场景：首次进入设置页后保存配置
- **当** 用户首次打开设置页，后端在保存时补齐了 `device_id` / `device_name`
- **则** 前端保存成功后立即显示最新值，无需退出应用重新进入

### 需求：日报导出文件名区分设备
当用户启用日报自动保存，或在日报页手动导出 Markdown 时，导出文件名应包含设备标识，避免同一天不同设备的日报互相覆盖。

#### 场景：导出综合日报
- **当** 导出“全部设备”视角的综合日报
- **则** 文件名使用 `<date>.all.md`

#### 场景：导出单设备日报
- **当** 导出某台具体设备的日报
- **则** 文件名使用 `<date>.<device_id>.md`
